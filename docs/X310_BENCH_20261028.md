# X310 initial bench verification — 28 October 2026

The connected radio passes transport and bounded paired recording checks. RF phase
calibration and bearing accuracy are **not verified**: the operator confirmed
antennas or no known reference signal at the RX2 inputs. No drone was supplied.
All operations were receive-only; no firmware update or IQ download was performed.

Evidence remains in `data/analysis/x310_bench_20261027/`, retaining the directory
name established when this bench session began. Dates in raw logs are host supplied.

The official UHD soak discards samples. It tests radio/network transport, not the
application's paired decoder, disk writer or GUI under continuous load. The short
paired captures verify timestamp continuity and equal channel lengths; they do
not measure RF phase alignment. UHD emits a tick-rate-zero warning during timed
initialization; successful receipt alone is not proof of phase synchronization.
Ambient RF-event counts are detector output, not a drone count or O4 accuracy.

The native screenshot exposed clipped direction-panel controls/counters. The cancel
button now has its own row and status text wraps within the panel. This visual
check does not cover manual button interaction or recovery after cable removal.
Uncalibrated paired replay now displays reference `none` and leaves calibration
IDs empty instead of exposing the default `splitter@0` placeholder. A worker
regression verifies no accepted bearings and no claimed reference in that state.

## Hardware metadata changes

`UsrpSource::hardware_state()` queries board identifiers/serials, UHD/FPGA,
clock/time sources, reference/LO sensors, actual rates/frequencies/gains/antennas,
bandwidth and RF/DSP tune results. The paired recorder checks both configurations
and locks before and after capture, then publishes those fields in the manifest.
Sensors are **not continuously monitored** during capture. Existing offline
manifests remain supported without being relabeled as hardware-observed evidence.

The first metadata capture exposed an installed-driver discrepancy: requesting
10 MHz bandwidth made the getter return 10 MHz even though the UBX probe reports
a fixed 160 MHz range. The source now clips requests to the advertised supported
range before setting bandwidth. `paired_observed_bw` confirms 160 MHz afterward;
earlier manifests are preserved as historical evidence, not rewritten.

Rig/cable labels are explicitly `unverified_inputs` / `unverified`. The default
0.05 m spacing and zero orientation are nominal values, not measured antenna
geometry. These captures must not be used as a known calibration reference.
